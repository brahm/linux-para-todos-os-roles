Em resumo

O que faz e o que não faz

Todas as receitas deste rolê existem, e ele já aparece no menu do bora. Toda semana, cada receita é aplicada, conferida e desfeita em máquinas virtuais de verdade, no Ubuntu 24.04, no Ubuntu 26.04 e no Debian 13, inclusive com a tela de login e o navegador; o registro de testes de cada receita mostra a última vez. Cada receita sabe se desfazer e, com o snapshot do sistema configurado, o bora tira um antes de aplicar.

✓O que o rolê faz

  • Configura o Git com seu nome e seu e-mail, e cria uma chave SSH para o GitHub ou o GitLab.
  • Instala as ferramentas de compilação que muitos pacotes de Python e de Node.js pedem na instalação.
  • Prepara o Python para projetos, com ambientes virtuais, sem mexer no Python que a distro usa.
  • Instala o Node.js LTS oficial, conferido pela soma SHA256, com o npm install -g funcionando sem sudo.
  • Liga os contêineres com Podman, que rodam na sua conta, sem permissão de administrador, e acham as imagens do Docker Hub pelo nome curto.

✕O que ele não faz

  • Não escolhe um editor por você. Use o que quiser; o rolê Vibecodar pergunta qual instalar.
  • Não usa sudo com pip ou npm, que é a origem de muitos sistemas quebrados.
  • Não troca o Python do sistema por outra versão.
  • Não cria contas no GitHub ou no GitLab por você.

Passo a passo

Como o bora leva você até lá

  1. Escolha o rolê no menu

    Rode sudo bora no terminal. O menu mostra só os rolês que cabem na sua máquina e na sua distro, e você escolhe pelo número.

  2. Responda o que for preciso em português

    Para este rolê, o bora pergunta:

    • Por onde você quer começar: Python ou web, com Node.js? (o padrão é Python)
    • Que nome vai nos seus commits? (o padrão mantém o que já estiver no Git, ou usa o nome da sua conta)
    • Que e-mail vai nos seus commits? Use o mesmo da sua conta no GitHub ou no GitLab.

  3. Revise o plano nada mudou ainda

    O bora mostra o plano: as receitas, na ordem, com os parâmetros. Você pode aplicar agora, só simular, ou salvar o plano para revisar com calma, versionar ou aplicar em outra máquina.

  4. Snapshot antes de mudar o ponto de volta

    Se o snapshot do sistema já estiver configurado, o bora tira uma foto do sistema antes da primeira mudança. Se o próprio rolê configura o snapshot, as próximas mudanças já ganham o ponto de volta.

  5. Uma receita de cada vez verificar, aplicar, testar

    Cada receita primeiro verifica se já está aplicada, e pula se estiver. Depois aplica e testa. Se uma falhar, o bora para ali, diz o que aconteceu e como voltar. As 6 receitas deste rolê estão logo abaixo.

  6. Pronto quando o teste que qualquer pessoa faz

    Um projeto de exemplo é criado e versionado no Git, roda num ambiente virtual do Python ou no Node.js, e podman run --rm hello-world mostra a mensagem do contêiner de teste.

  7. Para voltar atrás sudo bora desfazer

    O bora remove o que instalou e volta a configuração do Git ao que era. Os seus projetos e a chave SSH ficam onde estão.

Os porquês

Por que assim

Por que ambientes virtuais?

A distro usa o próprio Python para funcionar. Instalar pacotes nele pode quebrar programas do sistema, e por isso as distros novas já bloqueiam o pip global. Cada projeto ganha o seu ambiente.

Por que Podman, e não Docker?

O Podman roda contêineres no seu usuário, sem um serviço como root por trás, e aceita os mesmos comandos do Docker na maioria dos casos.

Por que dois perfis?

Quem vai para web precisa de Node.js; quem vai para dados e automação precisa de Python. Instalar só o que você vai usar deixa o computador mais simples de entender. Para ter os dois, aplique o rolê de novo com o outro perfil.

Por que o Node.js de nodejs.org, e não o da distro?

No Ubuntu 24.04 e nas derivadas, o Node.js da distro é a versão 18, que já saiu de suporte e não roda as ferramentas de hoje, como o Vite. O bora instala a versão LTS que o projeto testou, igual em todas as distros, e só se o arquivo baixado bater com a soma SHA256 gravada na receita.
