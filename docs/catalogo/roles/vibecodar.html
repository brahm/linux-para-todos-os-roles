Em resumo

O que faz e o que não faz

Este rolê ainda está no papel. As receitas tracejadas não existem, e os detalhes podem mudar. As receitas prontas (Sistema atualizado, Git, Python com ambientes virtuais, Node.js) já funcionam hoje, como receitas avulsas no menu do bora.

✓O que o rolê faz

  • Tudo do “Começar a programar”, mais ripgrep, fd, jq e o GitHub CLI, que os agentes usam o tempo todo.
  • Instala os agentes que você escolher (Claude Code, Codex, Copilot CLI, Antigravity CLI, Mistral Vibe ou OpenCode) pelos instaladores oficiais, que o bora baixa, confere e mostra antes de rodar.
  • Guarda as chaves de API num arquivo em ~/.config que só você lê, e configura o OpenCode com a sua chave, se você tiver uma.
  • Confere cada commit com o gitleaks, para nenhuma chave ir parar no GitHub por engano.
  • Coloca os agentes numa caixa de areia, se você quiser, onde eles não enxergam o sistema todo.

✕O que ele não faz

  • Nenhum agente recebe sudo. Quem aplica mudanças no sistema é sempre você, pelo bora.
  • Não guarda chave nenhuma no repositório nem manda as suas chaves para lugar nenhum.
  • Não assina planos pagos nem cria contas por você.
  • Não esconde que este é o rolê que mais quebra: os agentes mudam de instalador o tempo todo, e as receitas são conferidas a cada versão do bora.

Passo a passo

Como o bora leva você até lá

  1. Escolha o rolê no menu

    Rode sudo bora no terminal. O menu mostra só os rolês que cabem na sua máquina e na sua distro, e você escolhe pelo número.

  2. Responda o que for preciso em português

    Para este rolê, o bora pergunta:

    • Quais agentes você quer?
    • Vai usar chave de API (OpenRouter, DeepSeek ou outra)?
    • Qual editor: VS Code, VSCodium, Zed ou só o terminal?
    • Quer isolar os agentes numa caixa de areia?

  3. Revise o plano nada mudou ainda

    O bora mostra o plano: as receitas, na ordem, com os parâmetros. Você pode aplicar agora, só simular, ou salvar o plano para revisar com calma, versionar ou aplicar em outra máquina.

  4. Snapshot antes de mudar o ponto de volta

    Se o snapshot do sistema já estiver configurado, o bora tira uma foto do sistema antes da primeira mudança. Se o próprio rolê configura o snapshot, as próximas mudanças já ganham o ponto de volta.

  5. Uma receita de cada vez verificar, aplicar, testar

    Cada receita primeiro verifica se já está aplicada, e pula se estiver. Depois aplica e testa. Se uma falhar, o bora para ali, diz o que aconteceu e como voltar. As 9 receitas deste rolê estão logo abaixo.

  6. Pronto quando o teste que qualquer pessoa faz

    Cada agente responde a um “olá” no terminal, e um projeto de exemplo é criado, versionado e passa pela verificação de segredos.

  7. Para voltar atrás sudo bora desfazer

    O bora remove os agentes, a caixa de areia e o gitleaks que instalou. O arquivo de chaves fica, para você decidir se apaga.

Toque numa receita pronta para ver o passo a passo dela. Os ids das planejadas são provisórios.

Os porquês

Por que assim

Por que caixa de areia?

Um agente roda comandos no seu computador. Numa caixa de areia, um comando errado apaga, no máximo, o que está dentro dela.

Por que o gitleaks?

Colar uma chave de API num arquivo e fazer commit é o acidente mais comum de quem começa com agentes. O gitleaks barra o commit antes.

Por que qualquer agente serve?

O rolê não depende de um fornecedor. Quem não tem cartão consegue usar agentes com cota gratuita ou modelos locais.
