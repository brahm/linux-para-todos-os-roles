Python com ambientes virtuais

Prepara o Python para projetos, com ambientes virtuais, pip e pipx, sem mexer no Python que a distro usa.

dev/python Risco baixo Pede a senha de administrador Testada em contêiner no Ubuntu e no Debian
Ver o passo a passo Ver o código

Em resumo

O que faz e o que não faz

✓O que faz

  • Instala o módulo de ambientes virtuais e o pip, para cada projeto ter as suas bibliotecas.
  • Instala os cabeçalhos do Python, que os pacotes com partes em C pedem para compilar.
  • Instala o pipx, para programas de linha de comando escritos em Python.
  • Faz o comando python abrir o Python 3, como os tutoriais escrevem.
  • Cria a pasta ~/.local/bin, onde o pipx põe os programas, para ela entrar no PATH.

✕O que não faz

  • Não troca a versão do Python da distro.
  • Não instala nada com sudo pip, que pode quebrar programas do sistema.
  • Não cria projetos nem ambientes por você.
  • Não apaga os ambientes virtuais dos seus projetos no desfazer.

Passo a passo

Como o bora aplica esta receita

As mesmas quatro etapas de toda receita, com o que esta confere em cada uma.

  1. Verificar já está aplicada?

    Confere se python3-venv, python3-pip, python3-dev, pipx e python-is-python3 estão instalados, e se a pasta ~/.local/bin existe.

  2. Aplicar faz a mudança

    Instala os pacotes que faltarem e cria ~/.local/bin, como a própria pessoa. O ~/.profile põe essa pasta no PATH a cada login.

  3. Testar funcionou?

    Confere que python e python3 mostram a mesma versão, cria um ambiente virtual de verdade numa pasta temporária e roda o pip de dentro dele, e confere o Python.h e o pipx.

  4. Desfazer quando você pedir

    Remove os pacotes que a receita instalou e a pasta ~/.local/bin, se ainda estiver vazia. Os ambientes dos projetos ficam.

Os porquês

Por que assim

Por que não sudo pip install?

O Python da distro é usado por programas do próprio sistema. Trocar uma biblioteca dele pode quebrar esses programas. Por isso, desde o Debian 12 e o Ubuntu 23.04, o pip fora de um ambiente virtual recusa instalar, com o erro externally-managed-environment.

O que é um ambiente virtual?

Uma pasta, em geral .venv, dentro do projeto, com um Python e as bibliotecas só daquele projeto. Dois projetos podem usar versões diferentes da mesma biblioteca. Apagar a pasta apaga tudo, sem rastro no sistema.

E o pipx?

É para programas, e não para bibliotecas: pipx install ruff cria um ambiente só para o ruff e põe o comando em ~/.local/bin. Atualizar ou remover um não mexe nos outros.

Como

O que muda no sistema

  • python3-venv, python3-pip e python3-devOs ambientes virtuais, o pip dentro deles e os cabeçalhos para compilar.
  • pipx e python-is-python3Programas em Python em ambientes próprios, e o comando python.
  • ~/.local/binCriada vazia, se ainda não existir. Entra no PATH no próximo login.

Parâmetros

O que dá para escolher

ParâmetroPadrãoO que é
usuarioautoA conta que vai programar, para a pasta ~/.local/bin, onde o pipx põe os programas. "auto" é quem rodou o bora com sudo.

No menu, o bora pergunta o que precisa. Num script ou num agente, passe os parâmetros na linha de comando:
bora plano --receitas dev/python -p dev/python.usuario=auto

Confira você mesmo

Os comandos para conferir

python3 -m venv .venvCria um ambiente virtual na pasta do projeto.
source .venv/bin/activateEntra no ambiente. O prompt passa a mostrar (.venv); para sair, deactivate.
pipx install ruffInstala um programa de linha de comando no seu próprio ambiente.
