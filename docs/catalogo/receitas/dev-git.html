Git

Instala o Git com o seu nome e o seu e-mail nos commits, e cria uma chave SSH para o GitHub ou o GitLab.

Em resumo

O que faz e o que não faz

✓O que faz

  • Instala o Git, se ainda não estiver instalado.
  • Põe o seu nome e o seu e-mail nos commits, para o primeiro git commit não parar pedindo.
  • Começa os repositórios no ramo main, o mesmo nome do GitHub e do GitLab.
  • Deixa o git pull juntar as mudanças sozinho, sem parar com uma pergunta que quem começa ainda não sabe responder.
  • Cria uma chave SSH e mostra a linha para colar no GitHub ou no GitLab.

✕O que não faz

  • Não cria conta no GitHub nem no GitLab, e não cadastra a chave por você.
  • Não apaga o que já estava no seu .gitconfig: só acrescenta.
  • Não cria outra chave SSH se você já tiver uma.
  • Não apaga a chave no desfazer: ela pode já estar cadastrada no site.

Passo a passo

Como o bora aplica esta receita

As mesmas quatro etapas de toda receita, com o que esta confere em cada uma.

  1. Verificar já está aplicada?

    Confere se o Git está instalado e se o nome, o e-mail, o ramo inicial e o jeito de juntar do git pull já estão como a receita pede, e se a pessoa já tem uma chave SSH.

  2. Aplicar faz a mudança

    • Instala git e openssh-client, se faltarem.
    • Guarda uma cópia do ~/.gitconfig e grava user.name, user.email e, se não existirem, init.defaultBranch e pull.rebase, como a própria pessoa.
    • Cria ~/.ssh/id_ed25519, se não houver chave, e mostra a parte pública.

  3. Testar funcionou?

    Confere cada configuração, faz um commit de verdade num repositório de teste, apagado no fim, e confere a chave com ssh-keygen -l.

  4. Desfazer quando você pedir

    Volta o ~/.gitconfig ao que era, ou apaga o arquivo, se foi a receita que o criou, e remove os pacotes que ela instalou. A chave SSH fica.

Os porquês

Por que assim

Por que o nome e o e-mail?

Cada commit leva o nome e o e-mail de quem fez. O GitHub e o GitLab usam o e-mail para ligar o commit à sua conta, por isso vale usar o mesmo de lá. Sem eles, o Git se recusa a fazer o commit.

Por que main?

É o nome que o GitHub e o GitLab dão ao ramo principal. Com outro nome no seu computador, o primeiro git push cria um ramo a mais, e os tutoriais deixam de bater com o que você vê.

Por que pull.rebase = false?

Quando você e outra pessoa mudam o mesmo repositório, o git pull precisa juntar as duas versões. Sem essa configuração, o Git para e pede que você escolha entre merge, rebase e fast-forward. O merge é o comportamento clássico e o que os tutoriais esperam.

Por que uma chave SSH, e sem senha?

O GitHub não aceita mais a senha da conta no git push. A chave é o jeito recomendado e não expira. Ela é criada sem senha porque a receita não faz perguntas no meio; para pôr uma, rode ssh-keygen -p -f ~/.ssh/id_ed25519.

Como

O que muda no sistema

  • git e openssh-clientInstalados se ainda não estiverem.
  • ~/.gitconfiguser.name, user.email, init.defaultBranch e pull.rebase. O que já estava lá fica.
  • ~/.ssh/id_ed25519 e id_ed25519.pubA chave SSH, só se a pessoa ainda não tiver uma.

Parâmetros

O que dá para escolher

ParâmetroPadrãoO que é
nomeautoQue nome vai nos seus commits? "auto" mantém o que já estiver configurado, ou usa o nome da sua conta neste computador.
emailNoneQue e-mail vai nos seus commits? Use o mesmo da sua conta no GitHub ou no GitLab. Em branco, mantém o que já estiver configurado.
chave_sshsimCriar uma chave SSH para o GitHub ou o GitLab, se a pessoa ainda não tiver uma.
usuarioautoA conta que vai programar. "auto" é quem rodou o bora com sudo.

No menu, o bora pergunta o que precisa. Num script ou num agente, passe os parâmetros na linha de comando:
bora plano --receitas dev/git -p dev/git.chave_ssh=nao

Confira você mesmo

Os comandos para conferir

git config --global --listMostra tudo o que está configurado no seu Git.
cat ~/.ssh/id_ed25519.pubMostra a parte pública da chave, para colar no GitHub ou no GitLab.
ssh -T git@github.comDepois de cadastrar a chave, responde com o seu usuário do GitHub.
