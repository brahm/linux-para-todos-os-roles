Acesso por SSH

Liga o servidor SSH para entrar neste computador pelo terminal de outro, só pela rede local, sem login do root e, se você quiser, só com chave.

seguranca/ssh Risco médio Pede a senha de administrador Testada em máquina virtual no Ubuntu e no Debian

Em resumo

O que faz e o que não faz

✓O que faz

  • Liga o servidor SSH, para entrar nesta máquina pelo terminal de outro computador da casa.
  • Fecha o que uma máquina de casa não precisa: o login do root, as senhas vazias e o encaminhamento de janelas.
  • Libera só a rede local no firewall, quando ele está ligado.
  • Aceita só chave, se você pedir, e só depois de conferir que a conta já tem uma.

✕O que não faz

  • Só entra se você pedir: o padrão do rolê é não ligar o SSH.
  • Não abre porta para a internet. Para entrar de fora de casa, o caminho é uma VPN.
  • Não desliga a senha numa conta sem chave, para ninguém ficar trancado do lado de fora.
  • Não cria contas nem chaves por você.

Passo a passo

Como o bora aplica esta receita

As mesmas quatro etapas de toda receita, com o que esta confere em cada uma.

  1. Verificar já está aplicada?

    Confere se o openssh-server está instalado, se a configuração do bora está no lugar e, com o firewall ligado, se a rede local está liberada.

  2. Aplicar faz a mudança

    Instala o servidor, escreve /etc/ssh/sshd_config.d/10-bora.conf, confere com sshd -t antes de recarregar, liga o SSH no boot e acrescenta a regra do firewall para a rede local.

  3. Testar funcionou?

    Confere a configuração válida, os valores que valem de verdade com sshd -T, o SSH ligado no boot, a porta 22 esperando conexões e a regra do firewall.

  4. Desfazer quando você pedir

    Remove a regra do firewall e o arquivo da receita, desliga o que ela ligou e tira o openssh-server, se foi ela que instalou. Quem está conectado na hora continua.

Os porquês

Por que assim

Para que SSH numa máquina antiga?

Uma máquina antiga que vira servidor da casa costuma ficar num canto, sem tela nem teclado. O SSH é o jeito de cuidar dela de outro computador: atualizar, ver o espaço em disco, reiniciar um serviço.

Senha ou chave?

A senha funciona na hora e serve para começar. A chave não dá para adivinhar e é o recomendado depois que você copiar a sua com ssh-copy-id. Aí é só rodar o bora de novo com so_chave em sim.

Por que só a rede local?

Nenhuma receita do bora abre porta para a internet: depende do roteador, do provedor e do CGNAT, e uma porta de SSH aberta recebe tentativas de senha o dia inteiro. De fora de casa, use uma VPN, como o Tailscale.

Como

O que muda no sistema

  • openssh-serverO servidor SSH. Cria as chaves do servidor na instalação.
  • /etc/ssh/sshd_config.d/10-bora.confSem login do root, sem senha vazia, no máximo 4 tentativas e, se você pedir, só chave.
  • ssh.socket ou ssh.serviceO SSH liga junto com o computador.
  • Regra do ufw bora-sshA porta 22 liberada só para a rede local, quando o firewall está ligado.

Parâmetros

O que dá para escolher

ParâmetroPadrãoO que é
so_chavenãoAceitar só chave SSH, sem senha. Precisa que a conta já tenha uma chave em ~/.ssh/authorized_keys.
usuarioautoA conta que vai entrar por SSH, usada para conferir a chave quando so_chave é sim. Com auto, é quem rodou o bora com sudo.
rede_localautoA rede da casa, como 192.168.0.0/24, liberada no firewall quando ele está ligado.

No menu, o bora pergunta o que precisa. Num script ou num agente, passe os parâmetros na linha de comando:
bora plano --receitas seguranca/ssh -p seguranca/ssh.so_chave=nao

Confira você mesmo

Os comandos para conferir

ssh pessoa@endereçoDe outro computador da casa, com o endereço que ip -4 addr mostra.
sudo sshd -T | grep -E 'permitrootlogin|passwordauthentication'Os valores que valem de verdade.
ssh-copy-id pessoa@endereçoCopia a sua chave para a máquina, para depois usar só chave.
