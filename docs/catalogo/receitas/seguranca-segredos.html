Verificação de segredos

O gitleaks confere cada commit e barra os que levam uma chave de API ou uma senha, e o Git passa a ignorar os arquivos .env e as chaves em todos os projetos.

Em resumo

O que faz e o que não faz

✓O que faz

  • Confere cada commit com o gitleaks e barra o que leva uma chave de API, um token ou uma senha.
  • Faz o Git ignorar os arquivos .env e as chaves privadas em todos os projetos, inclusive os que você clonar depois.
  • Mantém os ganchos de cada projeto funcionando: o gancho do bora chama o do projeto depois do gitleaks.

✕O que não faz

  • Não apaga segredos que já foram para o histórico: para isso, troque a chave no site do provedor.
  • Não passa por cima de um core.hooksPath que você já tinha.
  • Não roda nos projetos que definem os próprios ganchos com o husky ou o core.hooksPath do projeto.
  • Não impede um git commit --no-verify, para quando o gitleaks errar.

Passo a passo

Como o bora aplica esta receita

As mesmas quatro etapas de toda receita, com o que esta confere em cada uma.

  1. Verificar já está aplicada?

    Confere se o git e o gitleaks estão instalados, se o arquivo de exclusões globais tem o bloco do bora e se o core.hooksPath aponta para os ganchos do bora.

  2. Aplicar faz a mudança

    • Para, sem mudar nada, se a conta já usar outro core.hooksPath.
    • Acrescenta o bloco do bora ao ~/.config/git/ignore (ou ao arquivo do core.excludesFile).
    • Cria ~/.config/git/ganchos-bora, com o gancho e um link para cada nome de gancho, e configura o core.hooksPath.

  3. Testar funcionou?

    Num repositório de teste, como a pessoa: um .env fica fora do Git, um commit com um token do GitHub inventado é barrado, um commit sem segredo passa e um gancho do próprio projeto continua rodando.

  4. Desfazer quando você pedir

    Tira o core.hooksPath e o bloco do bora, apaga os ganchos e remove os pacotes que a receita instalou. As suas outras linhas ficam.

Os porquês

Por que assim

Por que não basta apagar o arquivo depois?

A chave continua no histórico do Git, e num repositório público robôs acham em minutos. O único conserto é trocar a chave no site do provedor. Por isso o melhor é não deixar entrar.

Por que nos ganchos da conta, e não em cada projeto?

Assim vale para todo projeto, inclusive os que você clonar amanhã, sem lembrar de instalar nada. O gancho do bora chama o .git/hooks de cada projeto depois, para não quebrar o que já existia.

E se o gitleaks errar?

Ele às vezes acha que um texto de exemplo é uma chave. Confira o que ele apontou e, se for alarme falso, faça o commit com git commit --no-verify.

Como

O que muda no sistema

  • git e gitleaksDos repositórios da distro.
  • ~/.config/git/ignoreUm bloco do bora com .env, *.pem, *.key e as chaves SSH.
  • ~/.config/git/ganchos-boraO gancho e os links; o core.hooksPath aponta para cá.

Parâmetros

O que dá para escolher

ParâmetroPadrãoO que é
usuarioautoA conta que vai programar. "auto" é quem rodou o bora com sudo.

No menu, o bora pergunta o que precisa. Num script ou num agente, passe os parâmetros na linha de comando:
bora plano --receitas seguranca/segredos -p seguranca/segredos.usuario=auto
