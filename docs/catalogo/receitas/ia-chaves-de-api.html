Chaves de API guardadas

Um arquivo para as chaves de API dos agentes de IA, fora de qualquer projeto e com permissão só do dono, carregado em cada terminal.

ia/chaves-de-api Risco baixo Pede a senha de administrador Testada em contêiner no Ubuntu e no Debian
Ver o passo a passo Ver o código

Em resumo

O que faz e o que não faz

✓O que faz

  • Cria um arquivo para as chaves de API em ~/.config/chaves-de-api, que só a sua conta abre.
  • Carrega as chaves em cada terminal novo, onde os agentes as procuram.
  • Diz onde criar cada chave, com o provedor que você escolheu no topo do arquivo.

✕O que não faz

  • Não recebe a sua chave pelo bora: o plano pode ir para o Git ou para uma IA, então você cola a chave no arquivo, depois.
  • Não manda as chaves para lugar nenhum.
  • Não apaga o arquivo no desfazer se você já colou alguma chave.

Passo a passo

Como o bora aplica esta receita

As mesmas quatro etapas de toda receita, com o que esta confere em cada uma.

  1. Verificar já está aplicada?

    Confere se a pasta e o arquivo existem, com as permissões 700 e 600 e a sua conta como dona, e se o .bashrc tem o bloco do bora.

  2. Aplicar faz a mudança

    • Cria a pasta e o arquivo, se não existirem, já com a permissão só da pessoa.
    • Acrescenta ao .bashrc o bloco que carrega o arquivo.

  3. Testar funcionou?

    Confere as permissões, que outra conta não lê o arquivo, que ele não tem erro de sintaxe e, com uma chave de teste num arquivo temporário, que a chave chega ao terminal.

  4. Desfazer quando você pedir

    Tira o bloco do .bashrc. O arquivo só sai se continuar sem nenhuma chave.

Os porquês

Por que assim

Por que não no próprio projeto?

Um .env no projeto é o caminho mais curto para a chave ir parar no GitHub. Fora de qualquer projeto, nenhum git add alcança.

Por que o bora não pergunta a chave?

O plano do bora é um arquivo que pode ir para o Git, ser mostrado a uma IA ou aplicado em outra máquina. Uma chave ali vazaria. Você cola a chave direto no arquivo, num editor.

Qual provedor escolher?

O OpenRouter dá acesso a vários modelos com uma chave só, alguns gratuitos. A DeepSeek costuma ser das mais baratas. Os planos mudam o tempo todo; confira na página de cada um.

Como

O que muda no sistema

  • ~/.config/chaves-de-api/chaves.envPermissão 600, com uma linha comentada por provedor.
  • ~/.bashrcUm bloco do bora que carrega o arquivo em cada terminal novo.

Parâmetros

O que dá para escolher

ParâmetroPadrãoO que é
provedornenhumVai usar chave de API de algum provedor?
  • nenhum: Não vou usar chave de API por enquanto.
  • openrouter: OpenRouter, que dá acesso a vários modelos, alguns gratuitos.
  • deepseek: DeepSeek, com a API dos modelos da DeepSeek.
  • outro: Outro provedor, como Anthropic, OpenAI, Google ou Mistral.
usuarioautoA conta que vai programar. "auto" é quem rodou o bora com sudo.

No menu, o bora pergunta o que precisa. Num script ou num agente, passe os parâmetros na linha de comando:
bora plano --receitas ia/chaves-de-api -p ia/chaves-de-api.provedor=openrouter

Confira você mesmo

Os comandos para conferir

ls -l ~/.config/chaves-de-apiMostra que só você lê o arquivo (-rw-------).
printenv OPENROUTER_API_KEYNum terminal novo, mostra se a chave chegou.
