Contêineres com Podman

Instala o Podman, que roda contêineres na sua conta, sem permissão de administrador, e acha as imagens do Docker Hub pelo nome curto.

containers/podman Risco baixo Pede a senha de administrador Testada em contêiner no Ubuntu e no Debian
Ver o passo a passo Ver o código

Em resumo

O que faz e o que não faz

✓O que faz

  • Instala o Podman, que aceita os mesmos comandos do Docker na maioria dos casos.
  • Deixa os contêineres rodarem na sua conta, sem serviço como root e sem sudo.
  • Cria a faixa de IDs que os contêineres sem root precisam, se a conta ainda não tiver.
  • Acha as imagens pelo nome curto, como python ou nginx, no Docker Hub.

✕O que não faz

  • Não instala o Docker nem cria o grupo docker.
  • Não deixa nenhum serviço rodando: o Podman só roda quando você chama.
  • Não baixa imagem nenhuma: você escolhe o que rodar.
  • Não apaga as suas imagens e contêineres no desfazer: eles ficam em ~/.local/share/containers.

Passo a passo

Como o bora aplica esta receita

As mesmas quatro etapas de toda receita, com o que esta confere em cada uma.

  1. Verificar já está aplicada?

    Confere se podman e uidmap estão instalados, se a configuração dos registros está como a receita escreve e se a conta tem a faixa de IDs em /etc/subuid e /etc/subgid.

  2. Aplicar faz a mudança

    • Instala podman e uidmap.
    • Escreve /etc/containers/registries.conf.d/50-bora-docker-hub.conf, com o Docker Hub para os nomes curtos.
    • Se a conta não tiver faixa de IDs, guarda uma cópia de /etc/subuid e /etc/subgid e acrescenta 65536 IDs depois das faixas que já existem.

  3. Testar funcionou?

    Confere o podman --version, a faixa de IDs, a permissão do newuidmap, que o podman info da pessoa diz rootless: true e que o Docker Hub está nos registros.

  4. Desfazer quando você pedir

    Apaga a configuração dos registros, volta /etc/subuid e /etc/subgid ao que eram e remove os pacotes que a receita instalou.

Os porquês

Por que assim

Por que Podman, e não Docker?

No Docker, um serviço roda como root, e quem está no grupo docker consegue, na prática, fazer qualquer coisa no sistema. O Podman roda cada contêiner na conta de quem chamou, e aceita os mesmos comandos na maioria dos casos.

O que é a faixa de IDs?

Dentro do contêiner, os programas costumam rodar como root. Do lado de fora, esse root vira um ID da faixa da sua conta, sem poder nenhum no sistema. O adduser já cria a faixa para contas novas; contas antigas podem não ter.

Por que o Docker Hub?

Os tutoriais escrevem podman run python, com o nome curto. Sem dizer onde procurar, o Podman do Ubuntu não acha a imagem. Com um registro só na lista, ele procura lá, como o Docker faz.

Como

O que muda no sistema

  • podman e uidmapO Podman e o newuidmap, que os contêineres sem root usam.
  • /etc/containers/registries.conf.d/50-bora-docker-hub.confunqualified-search-registries = ["docker.io"].
  • /etc/subuid e /etc/subgidUma faixa de 65536 IDs para a conta, só se ela ainda não tiver.

Parâmetros

O que dá para escolher

ParâmetroPadrãoO que é
usuarioautoA conta que vai rodar os contêineres. "auto" é quem rodou o bora com sudo.

No menu, o bora pergunta o que precisa. Num script ou num agente, passe os parâmetros na linha de comando:
bora plano --receitas containers/podman -p containers/podman.usuario=auto

Confira você mesmo

Os comandos para conferir

podman run --rm hello-worldBaixa e roda o contêiner de teste, que imprime uma mensagem e sai.
podman infoMostra a configuração; rootless: true quer dizer que roda sem root.
podman imagesLista as imagens baixadas. Para apagar tudo: podman system reset.
