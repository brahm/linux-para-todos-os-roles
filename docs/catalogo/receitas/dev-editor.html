Editor de código

Instala o VS Code, do repositório da Microsoft, ou o VSCodium ou o Zed, do Flathub.

dev/editor Risco baixo Pede a senha de administrador Testada em máquina virtual no Ubuntu e no Debian
Ver o passo a passo Ver o código

Em resumo

O que faz e o que não faz

✓O que faz

  • Instala o VS Code do repositório oficial da Microsoft, com a chave conferida pela impressão digital publicada.
  • Ou o VSCodium ou o Zed, do Flathub, publicados pelos próprios projetos.
  • Ou nada, se você escolher ficar só no terminal.

✕O que não faz

  • Não instala extensões: as dos agentes você escolhe dentro do editor.
  • Não usa o VS Code do Flathub, que não é da Microsoft e cujo terminal não enxerga os agentes.
  • Não apaga as suas configurações e extensões no desfazer.

Passo a passo

Como o bora aplica esta receita

As mesmas quatro etapas de toda receita, com o que esta confere em cada uma.

  1. Verificar já está aplicada?

    Com o VS Code, confere se o pacote code está instalado e se o repositório da Microsoft está como a receita escreve. Com o VSCodium ou o Zed, se o aplicativo está instalado pelo Flathub.

  2. Aplicar faz a mudança

    • VS Code: baixa a chave, confere a impressão digital, escreve /etc/apt/sources.list.d/vscode.sources e instala o code. Se a chave não for a publicada, nada muda.
    • VSCodium ou Zed: instala do Flathub, que precisa estar ligado.

  3. Testar funcionou?

    VS Code: o pacote veio da Microsoft, a chave é a publicada e code --version responde. VSCodium ou Zed: o flatpak info acha o aplicativo.

  4. Desfazer quando você pedir

    Remove o editor e, no VS Code, o repositório e a chave da Microsoft.

No terminal

Uma aplicação de verdade

A saída de um teste no Ubuntu 24.04, no rolê Vibecodar com o VS Code, encurtada nas linhas do apt.

Os porquês

Por que assim

Por que o VS Code vem da Microsoft, e não do Flathub?

O do Flathub é empacotado por voluntários, e o terminal dele roda dentro do Flatpak, sem enxergar os agentes instalados na sua conta. O repositório da Microsoft é o caminho que ela recomenda, e a receita confere a chave como faz com o Firefox da Mozilla.

VS Code ou VSCodium?

O código é o mesmo. O VSCodium tira a telemetria e a marca da Microsoft, mas usa outra loja de extensões, que nem sempre tem as extensões oficiais dos agentes.

E o terminal no VSCodium e no Zed?

No Flathub, o terminal integrado pode rodar dentro do Flatpak. Se o agente não aparecer nele, use o terminal do sistema, ao lado do editor.

Como

O que muda no sistema

  • /etc/apt/keyrings/packages.microsoft.ascA chave da Microsoft, só com o VS Code.
  • /etc/apt/sources.list.d/vscode.sourcesO repositório do VS Code.
  • code, com.vscodium.codium ou dev.zed.ZedO editor escolhido.

Parâmetros

O que dá para escolher

ParâmetroPadrãoO que é
editorterminalQual editor você quer?
  • terminal: Só o terminal, sem editor novo.
  • vscode: VS Code, da Microsoft, o mais usado, com as extensões dos agentes.
  • vscodium: VSCodium, o VS Code sem a telemetria da Microsoft, pelo Flathub.
  • zed: Zed, leve e rápido, com agentes embutidos, pelo Flathub.

No menu, o bora pergunta o que precisa. Num script ou num agente, passe os parâmetros na linha de comando:
bora plano --receitas dev/editor -p dev/editor.editor=vscode

Testada em contêiner quer dizer que a receita passou nos testes automáticos dessa família, que rodam num contêiner a cada pull request, sem kernel, disco nem tela de login de verdade. Testada em VM quer dizer que, além disso, ela foi aplicada, conferida e desfeita numa máquina virtual (VM) de verdade, o que o CI faz toda semana; o registro acima mostra a última vez de cada distro. Enquanto uma receita só tem o teste em contêiner, o bora avisa quando monta o plano. Testar numa máquina sua é uma das ajudas mais valiosas.
